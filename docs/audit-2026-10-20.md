# Optimisation & QoL audit — 2026-10-20

Read-only audit of all 137 root pages, `js/*`, `theme.js`/`time.js`/`sw.js`, the Workers,
Cloud Functions and Pages proxies. Nine reviewers read each area in parallel; the highest-impact
findings were then re-read at the cited line by hand.

**Verification:** items marked ✔ were re-checked by me at the cited line. Bulk re-check of 32
reviewer citations matched 29 exactly; the 3 mismatches were re-located and are cited correctly
below. One finding (chat gallery listener) did **not** hold up on inspection and was dropped.

Severity is about a Kindle: jitless JS (5–10× slower), 7–15 fps e-ink, small RAM, slow Wi-Fi.

## P0 — correctness bugs users actually hit

### 1. Lite / Legacy / Kobo dashboard is a stale fork ✔
`build-automation.js:1703` replaces `index.html` with `index_old.html` for the Lite and Legacy
deploys; `index.html:12` also redirects `rekindle_layout=old` users there. `index_old.html` has
**zero** references to `validateLiveMatch` (index.html has 3) and zero to `matchmaking`.
So exactly the stale-listing bug AGENTS §11 fixed for main is still live for the oldest Kindles
and Kobas: ghost LIVE badges, lobbies that no longer exist, and no cleanup/heal.
*Fix:* move the dashboard body (app grid, favourites, live validation, badge) into
`js/dashboard.js` and keep only layout deltas in the two HTML files. Port the validator now
regardless.

### 2. Host disconnect destroys the match in six live games ✔
```js
mmRef.onDisconnect().remove();
matchRef.onDisconnect().remove();   // <-- matchRef is games/<type>/<id>
```
`livechess.html:552`, `livecheckers.html:567`, `liveconnect4.html:503`,
`livedotsandboxes.html:460`, `livetictactoe.html:548`, `liveyahtzee.html:578`.
`liveuno.html:657` and `livepictionary.html:689` already document why this is wrong. A host
network blip wipes the whole game node; nobody can finish the match.
*Fix:* delete those lines and copy liveuno's migration block (`players[gameState.host]` check,
`liveuno.html:896`) into all six — or extract the scaffold (see P2).

### 3. Dashboard agenda never reads Firestore ✔
```js
if (window.currentUser && window.db) {   // index.html:2880
```
`index.html:1322` declares `let currentUser = null;` — it is never exposed on `window`. The branch
is dead, so the agenda always falls back to `localStorage.rekindle_events_local` while
`calendar.html` writes only to `users/{uid}/events`. A user with a full calendar sees
"No events today." on the dashboard.
*Fix:* test the real bindings, and replace the unbounded `.get()` with a date-bounded query
(`.where('start','>=',startOfDay).where('start','<',endOfDay).limit(50)`).

### 4. Location is written obfuscated but read as plain JSON ✔
`settings.html:1753` / `:1989` call `setSecureItem('rekindle_location_manual', …)`, which
base64-XORs the value. Every consumer parses it raw:
`time.js:31`, `theme.js:307`, `js/i18n.js:15`, `index.html:2617`, `weather.html:838`, `maps.html:685`.
`time.js` throws into its `catch`, so `manualZone`/`utc_offset`/`country_code` are lost on every
page: DST handling degrades to the legacy numeric offset, `getUnitSystem()` never reaches its
manual branch, and i18n auto-language never resolves a country. Settings itself keeps working
because `deobfuscate()` is symmetric, so the split is invisible.
Second bug in the same path: `obfuscate()` does `btoa()` over UTF-16 code units, so a non-Latin1
city name ("Tokyo", CJK, Arabic) throws `InvalidCharacterError` outside any `try` — the picker
just sits there.
*Fix:* store plain JSON, migrate once (`try JSON.parse, else deobfuscate then rewrite`).

### 5. Pictionary host migration leaves clients with `isHost === false` ✔
`leaveMatch()` promotes a new host (`livepictionary.html:1496`), but `listenToMatch()` only does
`gameState = data;` — unlike `liveuno.html:912`, nothing recomputes `isHost`. The promoted client
therefore skips `if (isHost) setTimeout(advanceTurn, 5000)` (`:1028`) and every turn function
returns early, so the round-end screen stays up forever.
*Fix:* `isHost = (data.host === currentUser.uid);` inside the match listener and toggle
`#host-controls` from it.

### 6. Neighbourhood feed ignores `modified` docChanges ✔
`neighbourhood.html:2906`/`:2914` handle `added` and `removed` only. Both `editPost()`
(`:3833`) and the translate worker produce `modified`, so an admin edit does nothing on screen and
a fresh post stays in its original language until reload.
*Fix:* add a `modified` branch that re-renders that one card in place and updates `recentPosts`.

### 7. Calendar alert hides the wrong overlay ✔
`showModal()` writes into `#generic-modal-overlay` (`:1042`, DOM at `:2384`) but
`hideModal()` hides `#modal-overlay` (`:1062`) — the add/edit-event dialog. There is no X or
backdrop handler on the generic overlay, so any plain alert (e.g. "Title and Date required",
`:2211`) is unclosable **and** closes the editor the user was typing in.
*Fix:* `hideModal()` → `#generic-modal-overlay`; add a dismiss path.

### 8. Substack paging skips 70 % of every subscription ✔
```js
state.subOffset += 50;         // :1100
const subLimit = 15;           // :1137
```
Requests go out as `?limit=15&offset=<subOffset>`, so pages are 0–14, 50–64, 100–114… Posts
15–49, 65–99, … are unreachable until a full reload, and each extra page still costs
`ceil(subs/2)` worker requests.
*Fix:* `state.subOffset += subLimit;`.

### 9. Journal loses the last edits and then overwrites the good cache ✔
No `pagehide`/`visibilitychange` flush anywhere; the cloud write is a 1 s debounce
(`journal.html:901`), so closing straight after typing drops it. Worse, on reload
`loadCachedNotes()` restores the correct text and then the first snapshot does `notes = cloudNotes`
(`:886–889`) + `updateCache()` — permanently replacing the good cache with the stale document.
*Fix:* flush on `pagehide`, merge by `note.updated` instead of blind assignment.

### 10. Failed topic comment destroys the draft ✔
`topics.html:2655` clears the textarea before the `fetch` resolves and never restores it on the
error path (rate limit `retryAfter`, moderation rejection, offline). Up to 1000 characters typed
on an e-ink keyboard are lost. `isPostingComment` already prevents double submits.
*Fix:* clear only in the success branch; refocus the input on error.

### Also worth fixing while in there
- **Chat double-send race** ✔ — `setTimeout(() => isSendingMessage = false, 3000)`
  (`kindlechat.html:5473`) releases the guard while the POST is still in flight, and
  `getIdToken(true)` (`:5482`) routinely makes it slower than 3 s. Enter posts the same text twice
  while the button still looks disabled. Drop the timer; rely on `resetSendState()`.
- **Movies: one TMDB request per season, serially** — `watchlist.html:821`, inside the click
  handler, behind a dead "Saving…" button. Batch 3 at a time or lazy-load episodes.
- **Dropbox truncates folders at 500 entries** — `dropbox.html:1306` ignores
  `has_more`/`cursor`; files past 500 are invisible with no message.
- **Bible chapter race** — `bible.html:861` has no request id/abort, so two quick Prev taps can
  display chapter N while `saveState()` stored N+1.
- **RSS blob leak** ✔ — `rssreader.html:2019` creates an object URL per article and nothing calls
  `revokeObjectURL`; 20–30 articles grow RAM until the Kindle tab reloads.

### KindleChat (hottest page)

- **Pagination re-reads messages it already has** ✔ — `kindlechat.html:2941` calls
  `generalChatRef.child(id).once('value')` for up to 25 messages whose data was just stored in
  `generalMsgData[id]` (`:2927`). Up to ~50 concurrent RTDB GETs per scroll-to-top. Render from
  the cache.
- **Flipnote autoplay never stops** ✔ — `renderMessage` schedules `playFlipnote` for every
  flipbook bubble (`:5397`), and the loop only exits when the node disconnects (`:6293`). With
  three flipbooks in the feed that is three permanent 6 fps base64 `src` writes; every reaction
  or translation re-render re-arms them. Start on tap, keep the timer handle, clear on pagehide.
- **Translation arrivals rebuild whole bubbles** — `child_added` fires for the whole rendered
  window on load; each event rebuilds `innerHTML`, walks the tree for emoji, redraws the avatar
  and re-resolves the author (a `localStorage` parse per message). Patch `.msg-bubble` text when
  the node already exists.
- **ASCII picker scroll spy** — `:2666` reads `scrollHeight`/`clientHeight`, re-queries the
  sidebar and calls `scrollIntoView({behavior:'smooth'})` on every scroll event. Cache the
  metrics, query once, use `behavior: 'auto'` (smooth scrolling is an animation on e-ink).
- **Dead unmoderated send path** ✔ — `sendGeneralMessageViaWorker` / `sendGeneralMessageToRTDB`
  (`:5930`, `:5965`) have no callers and write straight to `kindlechat/messages`, bypassing the
  worker, rate limits and moderation. Only the rules stop them. Delete.

### Social feeds

- **Topic search rebuilds 200 rows per keystroke** ✔ — `oninput="renderSidebar()"`
  (`topics.html:867`) wipes and rebuilds the sidebar, re-running `renderEmojis` per row and
  re-filtering the 500-doc snapshot. A debounce helper already exists two functions above.
- **Topics listener re-maps all 200 docs per snapshot** — `:1328` ignores `docChanges()`; any
  comment in any topic repaints the whole sidebar. Use `docChanges()` + per-node patch.
- **Neighbourhood never detaches** — `postsListener` is assigned and never called, the scroll
  handler accumulates, and the file has zero `pagehide` handlers (topics.html already does this
  at `:3377`).
- **Admin-mode toggle loses paginated posts** — `:3010` re-renders from `recentPosts`, which
  `loadMorePosts` never appends to; the keys stay in `renderedPostKeys`, so they can't come back.
- **Poll votes** — `topics.html:2001` downloads the whole `pollVotes` collection per open and
  after each vote, counted client-side. Store an aggregate map on the topic.

### Readers

- **Gutenberg book is one DOM** ✔ — `reader.html:1942` allows 2,000,000 chars in a single
  `innerHTML`; `changeFont` writes `fontSize` then reads `scrollHeight` twice (`:2863`, `:2732`),
  so every font tap is a multi-second full-document layout on a long book. Mount by chapter and
  add `contain: layout style` to `#gb-pane p`.
- **RSS** ✔ — opening one article re-renders and re-decodes the whole list (`rssreader.html:1747`),
  and the blob URL leak above.
- **Books** ✔ — `books.html:530` clears both lists on every snapshot and recreates every
  `<img>` cover. Use `docChanges()` and patch status/stars in place.
- **Bible** — `bible.html:654` eagerly fetches ~272 KB of Dhammapada/Tao JSON even for the Bible
  (the lazy guards at `:918` prove it's unnecessary), and every Prev/Next is a fresh round trip.
- **Sheet music** — `onkeyup="filterScores()"` (`:592`) rebuilds 69 cards and 69 composer images
  per keystroke; composer images are cached in `localStorage` with no eviction.

### Media & integrations

- **Mail** — marking one email read calls `renderEmailList()` (`mail.html:1294`), rebuilding every
  row (and destroying scroll position); "load more" rebuilds all accumulated rows. Patch the one
  row / append the new page.
- **Bluesky** — returning from a profile always refetches 30 posts (`:849`) and re-requests every
  avatar/embed image (up to ~150 requests, no dimensions → reflow).
- **Calendar** — day view filters all events 24 times with a timezone conversion per event per
  hour (`:1476`); agenda converts 3× per event and builds an `eventsMap` it never uses. Convert
  once per event per render.
- **Timer** — `saveState()` writes 5 keys every second per running timer (`timer.html:982`,
  `:1579`); a 25-min session is ~7,500 synchronous writes. Save on transitions + every 30 s.
- **Reddit** — writes the raw RSS body per subreddit to `localStorage` on every view
  (`reddit.html:1150`) with no TTL/eviction; 30–40 subs accumulates megabytes toward the
  documented 64 MB cache wipe.
- **Pixel wallpaper editor** — `settings.html:1386` re-encodes a PNG (`toDataURL`) and writes
  storage per touched pixel during a drag; only the drag end needs it.

### Backend

- **`getSocialToken` does 5–8 serial hops per social page load** (`firebase-functions/index.js:1223–1298`),
  blocking `signInWithCustomToken` for chat/feeds/art. `Promise.all` the independent reads and
  drop the Console-visibility `getUser` from the request path.
- **`api/price.js` is the only proxy with no `caches.default`** ✔ — no Retry-After handling, no
  stale fallback, and a second Yahoo host on failure, while stocks fires one request per symbol
  and retries 3×. Copy the `reddit.js` cache block.
- **Stripe worker mints an OAuth token per call** (`workers/rekindle-stripe/worker.js:371`, `:644`,
  `:1103`, `:1141`) and refetches Google JWKs per checkout; the moderate worker already caches
  both (`worker.js:25`, `:545`).
- **`addToSupportersConfig` read-modify-writes the whole map** (`:958–999`) with no field mask —
  two concurrent webhooks drop a subscriber and their Pro.
- **Report submission blocks on Discord** (`worker.js:2594`) and two serial report patches, even
  though the report is already stored. Add `ctx.waitUntil`.
- **Mail callables** re-check Pro from scratch and open a cold IMAP connection per call, and
  `mail.html` awaits folders then emails serially — time-to-first-message is the sum.

## P3 — QoL polish

- **Report button is 20×20 px** ✔ (`neighbourhood.html:337`, `topics.html:328`) — the repo
  mandates 48×48. Inflate the hit area with padding/negative margin, keep the 20 px circle.
- **Emoji in UI copy renders as boxes on the Kindle** ✔ — `books.html:670` uses ⏳/✅ in the
  status dropdown (shown for every saved book), `mastodon.html:1120–1175` uses 🔁/💬/🔔/👤 in
  every toot and notification. Replace with ASCII/`icons.js` SVG per the no-emoji rule.
- **Settings shows stale custom-select labels** — `settings.html:1823/1881/2003` set `.value`
  after the widget painted, without dispatching `change`; `settings.html:1490` calls
  `window.rekindleRefreshCustomSelect()`, which **does not exist**. Add the refresh method and
  call it after each assignment.
- **58 silent `catch` blocks** (`catch(e){}`), 12 more with only a comment. Fine for genuinely
  best-effort work, but this is how the journal overwrite and the topics teardown bug hid.
  Log + surface once, per feature.
- **`console.log` left in production pages** — substack 15, reddit 14, dino 9, interactive 7,
  blockblast 7, mail 6. Cheap on a jitless engine and noisy in the field.
- **`getIdToken(true)` on every social write** — forces an Identity Toolkit round trip before
  each comment/message; the token is valid for an hour. Use the cached token, force-refresh once
  after a 401.
- **Transitions that need a reload** (language, scale, font) could apply live via the existing
  `rekindleApply*` hooks — lower priority than the above.

## Suggested sequence

1. **One-liners, low risk** — calendar `hideModal`, substack offset, dashboard agenda binding,
   theme.js duplicate init, pictionary `isHost`, `price.js` cache. Each is a few lines and
   independently shippable.

4. **Chat perf** — pagination cache, flipnote playback, translation patch-in-place, dead send
   path removal.
5. **Locale + shared assets** — skip/trim `en.json`, then `escapeHtml`/`showModal`/`drawAvatar`
   into shared modules and one `system7.css` (this one touches many files and needs the `?v=`
   bumps and a `npm run build` before deploy).

Every item above is a small, reviewable change; nothing requires a rewrite. The two large pieces
are the reader (chapter-mount the Gutenberg pane) and the live-game scaffold extraction.
